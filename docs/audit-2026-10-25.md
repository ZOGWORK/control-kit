# Control Kit audit, 2026-10-25

A full audit of Control Kit from scratch, run overnight at the owner's request. Four independent read-only passes each
reported findings with file references and reproductions:

- security and privacy;
- domain logic (quantities, matching, classification);
- the web app;
- production operations and catalog data.

Every finding was checked against the code before it was fixed. Fixes went through the usual gate: a PR, lint,
typecheck, unit and smoke tests, Greptile 5/5 on the exact head with no open threads, then merge and deploy. Greptile
found 22 more issues across the review rounds; all were fixed before merge.

The audit and its tests made **no Onshape requests and no AI calls**.

### Security and cost (#35)
- **Anyone could have broken sign-in for a day.** Every visit to `/oauth/start` wrote to KV before any login, and the
  free plan allows 1,000 writes a day. About 1,000 requests would have stopped sign-ins, scans, saved choices, and
  catalog updates until midnight UTC. Sign-in state now rides in a signed cookie; KV is written only after Onshape
  accepts a real login. The same change stops login CSRF.
- **Sessions** keep only your Onshape id and name (no email or company) and refresh once a day instead of on every
  panel load. Another site can no longer sign you out.
- **AI review** requests are rebuilt on the server from your own stored scan, so the key cannot be used to send other
  text. The daily limits (20 per person, 300 overall) live in an atomic Durable Object, so simultaneous reviews cannot
  exceed them. Saved answers cost nothing.
- **Other fixes:**
  - shared part types can only be set for parts in your scan;
  - STEP export polling stopped rewriting the job every 2 seconds;
  - only Onshape may embed the app (clickjacking).

### Quantities and matching (#36)
- **Undercounted orders.** Four screw bodies in one Part Studio, placed 30 times each, ordered 30 screws instead of
  120. Bodies in your own document now add up. A vendor's multi-body product (the REV switch) still counts once per
  place it sits.
- **Vanished parts.** Screws placed beside an imported motor were folded into it. Standard content is never folded now,
  and folding compares configurations.
- **Hidden subsystems.** Linked subassemblies named "Intake Wheels", "Servo Arm" and "Drive Motors" were listed as one
  bought item, hiding their parts. They expand again.
- **Wrong AndyMark prices.** A part numbered `1001` matched AndyMark `am-1001` exactly and was priced at $120. Bare
  numbers now match only vendors whose SKUs are bare numbers.
- **Made parts filed as fasteners.** "Captive Nut Plate", "Lead Screw", "Screw Jack" and similar were stock hardware.
- **Lost confirmations.** Confirmed matches were keyed by the document revision, so every edit dropped them. They are
  now saved per part and survive edits.

### Web app (#37)
- **Review rows (your screenshot):** inside Onshape's panel the buttons squeezed the part name to a few letters. Rows now
  stack by the list's own width: name and reason on top, actions below.
- **AI suggestions** go away when you decide a part yourself, instead of returning and overwriting your choice.
- **Keyboard review** works after clicking a filter or button. Holding a key no longer decides a run of parts.
- **Errors inside the part drawer** are shown in the drawer; before, they were hidden behind it.
- **Scans that end early** say so instead of silently going back to the start screen.
- **Saved scans** of old assemblies are pruned, so the browser's storage does not fill up.
- **Wording:** totals say they are public list prices before shipping and tax; your choices read "chosen by your team".

## Found, not fixed (your decision, or larger work)

- **Anyone who can read a public document can change its shared part types.** History records who. Limiting it to
  editors needs an Onshape permission check on each save, which costs a request.
- **Part pictures are now the main Onshape cost.** Yesterday 41 of 49 billable requests were pictures (one per part,
  the first time its drawer opens). The counter is about 193 of 2,500. Loading pictures only on a click would cut this.
- **STEP exports are not reused.** Exporting the same scan twice translates every part again, at about 3 requests per
  part. A per-revision file cache would make repeats free.
- **AndyMark and Pitsco totals.** 99% of AndyMark and 89% of Pitsco records have no verified pack size, so their Buy
  lines show no total. AndyMark appears to sell single items (a $0.35 screw). A "sold individually" rule needs the same
  page-by-page evidence check goBILDA and REV had first.
- **Stock unknown** on 281 multi-variant products (74 goBILDA, 207 ServoCity).
- **Catalog retirement backlog is invisible.** Each vendor keeps a replaced catalog for 24 hours, and no refresh starts
  while one is pending. Health and the ops report do not show it.
- **Known products are priced from the name alone.** "Color Sensor" is taken as REV's V3; this was deliberate in PR 10.
  A Limelight 3, or another brand's colour sensor, would be priced as the listed product.
- **The AI review could clear the last 34 too.** It could run by itself after each scan and apply confident answers.
  That would also let AI-picked vendor matches be priced, which changes the rule that only a person or an exact SKU
  confirms a match. Your call.
- **Development tools** (vitest, wrangler's undici) have published advisories. Production dependencies have none.
